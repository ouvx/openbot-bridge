# ローカルでセットアップする

1. 専用の作業ディレクトリを用意し、Node.js 24 とロックファイルから依存関係を復元します。初回の `npm ci --ignore-scripts` はレジストリに接続します。
2. `sh scripts/setup.sh` を実行します。初回にランダムな同意用パスコードを生成し、権限 0600 の `.env` に保存します。標準出力はファイルのパスだけです。既存の設定は保持し、0600 の通常ファイル以外は拒否します。
3. `.env` の `OPENBOT_DB` に、検証を許可された OpenBot 形式のデータベースのパスを指定します。省略時は現在のユーザーの標準設定ディレクトリを参照します。DB は読み取り専用で開きます。ブラウザから同意する際は、その同意画面の origin（スキーム、ホスト、ポート）を `BRIDGE_ALLOWED_ORIGINS` に完全一致で設定します。ポートを変える場合はこの値も合わせます。別の Bridge がある環境では `BRIDGE_PORT` を未使用のローカルポートにし、`BRIDGE_DATA_DIR` をこのインスタンス専用のディレクトリにします。
4. `BRIDGE_ALLOWED_AGENT_IDS` に公開対象として許可した ID だけをカンマ区切りで設定します。初期値は空です。`BRIDGE_READ_ONLY=1` と `BRIDGE_EXTENDED_TOOLS=0` を維持することで、一覧と接続確認に限定できます。基本機能では OpenBot の Local scripts 設定の変更は不要です。
5. `npm test` で模擬 DB と模擬通信先による直列テストを実行します。`npm run doctor` は設定した環境の診断です。`npm start` を実行し、ローカルの MCP クライアントで HTTP の `/mcp` を指定します。OAuth は動的クライアント登録と S256 PKCE を使い、読み取りスコープを選択します。同意用パスコードは自分が起動した Bridge の同意画面だけに入力してください。
6. 認証後は `openbot_health`、続いて `list_agents` を確認します。終了はサーバーを起動した端末で Ctrl+C を押します。

## 設定と確認範囲

`BRIDGE_PUBLIC_URL` は発行元を指定する設定です。この配布候補にはトンネルの起動、サービス登録、ChatGPT アカウント登録の自動処理は含まれていません。外部利用は [SECURITY.md](../SECURITY.md) の公開条件を解決してから判断してください。既存の運用用認証状態やジョブをテスト環境へ移さず、動作確認は模擬データから始めてください。

クライアントを分けるときは、管理者が登録済みクライアント ID と許可したエージェント ID 配列を対応させた JSON オブジェクトを `BRIDGE_CLIENT_AGENT_IDS` に設定します。全体の許可リストを超える ID は利用できません。空のオブジェクトは単一管理者用で、全クライアントの上限が共通になります。明示対応表がある場合は未登録の相手に対象を与えません。設定を反映してから新しく同意してください。以前の変数名 `BRIDGE_ALLOWED_AGENTS` は新しい名前を省略した場合のみ読みます。

### 資格情報のローカル検査

ローカル CLI は数値ループバックへ接続し、読み取り権限を既定にします。下記の出力先は新規の通常ファイルが必要です。内容はチャットやログに貼らず所有者が保管します。

```sh
node scripts/token.mjs --output data/local-reader.json
```

`--port` でローカルポートを変更できます。`--write`・`--admin` は明示した場合だけスコープを追加し、警告を表示します。更新時は同じ `client_id` と `resource` が必要です。更新時に `redirect_uri` を送る場合は認可時と一致させます。

### 操作を1件承認する

専用のローカル検証環境で書き込みを許可する管理者は、対象 ID を限定し、`BRIDGE_EXTENDED_TOOLS=1` と `BRIDGE_READ_ONLY=0` を明示して、対象操作のスコープで同意します。試験用 OpenBot の正式な書き込み経路が別途必要です。

1. クライアントが書き込みツールを呼び、`approval_required` と承認 ID を受け取ります。再送を識別する `idempotency_key` は任意です。同じ内容を別件として扱いたいときは最初から別のキーを指定します。
2. 管理者が Bridge と同じ設定とデータ領域を使うローカル端末で次を実行します。

   ```sh
   node scripts/approve.mjs APPROVAL_ID
   ```

3. 端末に表示される一時 URL をこの PC のブラウザで開き、主体・宛先・引数の全文を読んで承認または拒否します。カードの URL は1回の決定に使うキーを含みます。表示中は端末の画面共有・録画を止め、端末ログ・コマンド履歴・ブラウザ履歴に URL を残さないでください。承認用の待受は決定または期限で終了します。
4. 承認後、呼び出し側が同じ引数とキーに `approval_id` を加えて再送すると、1回だけ実行します。完了済みの結果を再取得するときは同じ引数とキーで `approval_id` を省略します。送達が不明な場合は管理者が記録を確認します。
